# おへやモンスター 設計書 v1.0（決定反映版）

- 日付: 2026-09-17 (JST)
- 対象デバイス: iPad (iPadOS 18+, Safari 18) 前提
- 依頼内容: iPadのカメラを使ったポケモンGO風ゲーム。部屋の中で床・テーブルを認識して、そこにモンスターが実在するように出現させる。
- 公開形態: Webアプリ (HTTPS) を GitHub Pages にデプロイ。公開URL + QRコード で配布。
- アプリ名: **おへやモンスター**（タイトル表記: おへやモンスター / ROMAN: Oheya Monster）

---

## 1. 概要・実現方式（最重要）

iPadのSafariは **Safari 18 / iPadOS 18 から WebXR Device API をネイティブ対応**している。
`immersive-ar` セッションで **ARKit に委譲**され、以下が標準Web標準APIで使える:

- `navigator.xr` + `requestSession('immersive-ar')` … カメラ透過のARセッション開始
- `hit-test` … カメラのレイが実在の平面(床・テーブル)に当たった点を返す
- `plane-detection` … 検出した水平/垂直平面の座標を取得
- `local-floor` 参照空間 … 実座標系の床基準
- **WebXR DOM Overlay** … カメラ画面上にHTMLのHUDを重ねる

⇒ **App Store不要。Webだけで完結。** GitHub Pages(HTTPS) + Safari で開くだけ。
これまで通り「公開URL + QRコード配布」の運用がそのまま使える。

### ハード要件
- iPadOS 18+ / Safari 18 以降であること（それ以前のiPadは WebXR AR非対応のため **Web版は不可** → その場合はARKitネイティブアプリの検討になる）
- 初回カメラ許可（Safariのカメラ権限ダイアログ）
- **HTTPS必須**（カメラ + WebXRのため）→ GitHub Pagesで満たす

## 2. 技術スタック

| 項目 | 採用 | 理由 |
|---|---|---|
| 言語 | TypeScript + Vite | 既存資産と同じ。型安全 |
| AR | WebXR (`immersive-ar` + `hit-test` + `plane-detection` + DOM Overlay) | iPad SafariでARKitに委譲、標準API |
| 3D | three.js (WebGL2) | WebXR AR標準サンプルもthree.js。ヒットテスト/平面検出の実装例が豊富 |
| モデル | 低ポリ自作 (three.jsプリミティブ合成) | コクテン決定: ゼロ資産・唯一無二 |
| サウンド | Web Audio 完全合成(発振器+ノイズ) | 他作品の教訓: ファイル型は静かに失敗する。合成は失敗しない |
| UI | DOM Overlay + 通常HTML | ARカメラ上にそのまま重ねられる |
| 保存 | localStorage | 図鑑・コレクション・設定の永続化（バックエンド不要） |
| デバッグ | 非ARフォールバックモード | ヘッドレスChrome/PCでARなしの仮想床に描画してUI検証 |

## 3. ゲーム画面フロー

```
タイトル画面 ──[ARを起動]──▶ カメラ許可 → immersive-arセッション開始
                                  │
                                  ▼
                    ARプレイ中（DOM Overlay）
                    ┌─ 平面検出: 床・テーブルを認識 → レティクル表示
                    ├─ モンスターが水平面上に出現（実寸で立つ）
                    ├─ タップ → 捕獲インタラクション（投げ/タイミング）
                    ├─ 捕獲成功 → 図鑑(コレクション)に追加
                    └─ HUD: 捕獲ボタン / 図鑑ボタン / サウンド / 終了
```

- 開始前: モンスター出現の「地面アンカー」として検出平面を利用。
- モンスターは一度出現したら同じ場所に留まり、視点を変えても固定（ワールドアンカー）されるのが「ちゃんとモンスターが出る」体感の肝。
- DOM Overlay にモンスターの名前・捕獲UI・図鑑ボタン等をHTMLで重ねる。

## 4. ゲームデザイン（ポケモンGO風・v1スコープ）

- **捕獲**: モンスターをタップ → **ボールを投げるフリックスワイプ**（GOっぽい）。コクテン決定。
- **図鑑**: 捕獲済みの種類とカウントを記録。部屋の中でどれだけ捕まえたか。
- **出現**: 検出平面上にランダム出現。捕獲数が増えるほどレアなモンスターが出現しやすくなる段階進行。
- **モンスター**: 見た目を差別化した複数種（水/草/炎 等のタイプ差し色、サイズ差）。
- **サウンド**: 出現SE、捕獲成功/失敗SE、図鑑BGM（Web Audio合成）。
- **設定永続化**: サウンドON/OFF等は localStorage 保持（他作品と同じ）。

## 5. サウンド・3Dモデルの方針

- **サウンド**: Web Audio 発振器+ノイズで完全合成。ゼロ資産=配布・ビルドが軽く、失敗しない。
- **モデル**: three.jsのプリミティブ(球・円錐・角柱)を組み合わせた**オリジナル低ポリ生物**（自作・ゼロ資産・コクテン決定）。

## 6. 品質・検証方針（ARはこの環境で検証不可のため）

- ARセッション(camera passthrough)は**ヘッドレスChromeで再現不可**。そこで:
  - **非ARフォールバックモード**を必ず搭載: AR非対応/デスクトップでは仮想の床にモンスターを描画。UI・HUD・捕獲・図鑑・サウンド・レイアウトをヘッドレスCDPで検証。
  - コンソールエラー0、DOM Overlay表示、図鑑の永続化、レイアウトを CDP で自動検証。
- **ARの実機動作はコクテンさんの実機iPadでのみ確認可能**。デプロイ後QRコードで開いてもらい、実機フィードバックで回収する（既存ワークフローと同じ）。
- 経験則: 不具合は「まず原因調査だけ」指示なら修正前に報告。UIはOKを出してから改修。
